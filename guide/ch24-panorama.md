# 第 24 章 AI 在研发流程中的全景图

::: info 本章要解决的问题
前面各章集中在“开发”这一个环节。把视野拉远到完整研发流程：

- 从需求到线上运维，AI 能介入哪些环节；
- AI 自动化、AI 线上巡检有哪些可行方案；
- 自动化程度怎样渐进，价值怎样验证。
:::

## 24.1 全景图：各环节的 AI 介入点

| 环节 | AI 介入点 | 复用本书哪些机制 |
|------|----------|-----------------|
| 需求 | 澄清问答（信息门禁）、历史需求与模块知识检索 | 第 20、21 章 |
| 设计 | 方案生成与对比、HTML 原型 | 第 23 章 |
| 开发 | 编码 Agent、子 Agent 协作 | 第 3~16 章 |
| 评审 | CodeReview：diff 风险分级、测试覆盖核对、知识库证据引用 | 第 20、21 章 |
| 测试 | 用例生成、回归任务编排、结果解读 | 第 18 章 |
| 发布 | 变更影响面摘要（知识图谱）、发布检查单、失败日志解读 | 第 21 章 |
| 线上 | 巡检、告警降噪、根因初判、oncall 报告 | 本章 |

观察这张表的正确方式：**每个介入点都不是新技术，而是同一个 Agent（循环 + 工具 + 权限 + 评测）换一组工具和触发时机**。研发流程的 AI 化，本质是把第 3~13 章的机制在不同数据源上复用。

## 24.2 AI 自动化的三个方向

1. **流程自动化**：定时或事件触发的 Agent 会话——cron 触发每日巡检，commit/PR 事件触发评审，发布事件触发回归。触发源从人变成事件，循环本身不变（第 4 章）；
2. **检查自动化**：把“人记得检查的事”变成 Agent 的固定任务——提交前检查、发布前检查、上线后回归。凡是能写成清单的检查，都值得交给 Agent 先跑一遍；
3. **知识自动化**：把散落的日志、指标、文档变成 Agent 可查的知识。第 21 章的方法从代码推广到运行数据：结构化、带证据、可增量更新。

## 24.3 AI 线上巡检：一个具体方案

线上是 AI 介入最谨慎的环节，也是收益最大的环节之一——因为线上问题的代价高、响应时间敏感。

**输入侧**：指标 API、日志检索、告警事件、变更记录——对 Agent 来说都是工具（第 5 章），巡检 Agent 带着这些工具按计划执行。

**任务侧**：

- 告警聚类降噪：把上百条告警归并为几个事件，附上受影响面；
- 异常解读：结合最近变更记录判断可疑度——“新版本发布后 10 分钟指标下跌”和“无变更时下跌”是完全不同的排查方向；
- 根因初判报告：给出证据链与置信度，明确标注哪些是推断——是“初判”不是“结论”；
- 定时巡检报告：趋势、阈值、未见过的异常模式，按固定格式产出。

**约束侧**（本书原则的直接复用）：

1. **只读优先**：巡检 Agent 默认只有读权限；
2. **写操作 fail-closed**（第 13 章）：任何变更、扩容、回滚动作必须审批或人在环；
3. **产出可审计**（第 22 章）：每次巡检报告记录查了什么、依据什么、结论置信度；
4. **结论必须带证据**：日志片段、指标链接；不确定就说不确定——同第 21 章“未验证标注”。

## 24.4 自动化程度的演进

```text
第一档：AI 建议，人执行      （评审意见、巡检报告）
第二档：AI 执行，人抽检      （自动生成测试、自动改简单问题）
第三档：AI 自动处理，事后审计 （自动回滚、自动扩容）
```

升档的条件是三件事同时满足：第 18 章的评测（固定任务、重复运行、成功率稳定）、第 22 章的指标（可复查的收益证据）、以及**回滚能力**——第三档的每个动作都必须可撤销。每升一档，错误的传播范围变大；自动化程度是风险决策，不是技术炫耀。

## 24.5 价值发挥的前提

- **数据通路**：日志、指标、事件能被 Agent 读取。很多团队卡在这里，而不是卡在模型能力；
- **权限模型**：最小权限加审批，先于自动化铺开；
- **可评测**：没有评测的自动化会静默退化——模型、依赖、数据格式任一变化都可能让成功率悄悄下滑；
- **警惕为自动化而自动化**：每个环节先问“频率 × 成本 × 风险”。低频、低险、人做很快的事，自动化它是负收益。

## 本章小结

- 研发流程的 AI 化 = 同一套 Agent 机制在不同环节换工具、换触发时机
- 三个方向：流程自动化、检查自动化、知识自动化
- 线上巡检可行，但必须只读优先、fail-closed、可审计
- 自动化分三档演进，升档靠评测、指标和回滚能力

最后一章离开技术，谈技术落地时绕不开的事：组织与分工怎样适配。
